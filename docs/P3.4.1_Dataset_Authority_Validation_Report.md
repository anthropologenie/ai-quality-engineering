**The gap this closed.** The gate had three consumers at HEAD — `scripts/run_retrieval.py`, `scripts/evaluate_retrieval.py`, and the builder's `main()` — and no test. Referential claims — chunk existence, document cataloguing, agreement with the parent QA pair — are absent here by design, following the boundary `scripts/build_evidence_trace.py` and `docs/CHUNK_VALIDATION_PLAN.md` §P5 already draw. They are §5's subject.

| Every referenced document resolves | X-10 `expected_source` is the cited fact's document; X-11 it is catalogued by the Manifest |
| Every referenced chunk resolves | X-12 exists in the committed corpus; X-13 belongs to `expected_source`; X-14 ascending `chunk_index` order (Decision G) |
| Complete provenance chains | X-15 entry → QA pair → cited fact → Document → spanning chunks ⊆ `expected_chunk`; X-16 every cited fact grounded in the entry's `expected_source` |

**Coverage, not equality, at X-15.** The chunks each cited fact resolves to must all appear in `expected_chunk`; the entry may carry more, because the field is a union over all cited facts. Asserting equality would rebuild the dataset — which the Repository Dependency Rule bars, and which would specify the builder rather than the committed relationships.

**One direction deliberately unasserted.** Facts are not required to be *onto* the QA Dataset: 7 of the 26 committed facts (`resume_f013`, `f014`, `f015`, `f018`, `f020`, `f023`, `f025`) are currently uncited. `docs/roadmap.md` §2.2 states *"one verified fact → many question forms"*, not that every fact yields a question, so requiring surjectivity would fail the repository for a state no authority forbids. Surjectivity **is** asserted for QA pairs → Evidence Trace (X-5), where the builder guarantees a bijection.

No runtime component is involved: no retriever is constructed and no retrieval is executed.

Where no repository function existed (the Golden Dataset and QA Dataset have no shipped validator), the record schema `datasets/SCHEMA.md` §8 deferred to *"the first implementation of each artifact type"* is frozen as-implemented, and value domains are taken from `docs/roadmap.md` §2.2/§2.3 rather than read off the data.

### Repository correctness

All three dataset authorities are internally well-formed and mutually consistent, exactly as committed. Every fact is grounded, uniquely locatable, and traceable to a catalogued document; every question resolves to committed knowledge; every expectation resolves to a real chunk of the right document, in the ratified order, with values matching the repository's own derivation rules.

### Observations

1. **The grounding guarantee was the repository's largest unprotected dependency.** Retrieval evaluation, metrics, and diagnosis are all anchored to `expected_chunk`, which is derived by locating `source_text` inside a document's character frame. Until this sprint, nothing on any automated path re-verified that anchor.

2. **The Evidence Trace gate was well-built and entirely untested.** All 19 of its failure classes reject correctly on first exercise; none required a fix. The absence was of coverage, not of correctness.

3. **Two provenance fields carry the same information with no mechanism keeping them in step.** `document_id` is joined on downstream; `document_source` is never read by any consumer, so drift in it could never fail a build. GD-7 is now the only thing holding them together.

4. **The two overlapping resume versions make several cross-dataset checks non-vacuous that would otherwise be formalities.** X-4, X-10, X-13 and X-16 can each distinguish a real authoring error on this corpus, because a fact cited from the wrong version resolves to real chunks containing similar text.

5. **The Golden Dataset artifacts are hand-authored and serialize with `ensure_ascii=False`**, unlike the builder-produced artifacts. Recorded rather than normalized — normalizing would mean modifying a repository authority.

6. **Corpus scale is recorded, not glossed.** 26 facts, 22 QA pairs, 22 Evidence Trace entries, 172 chunks, 2 documents. No specification asserts a count; every quantified specification first asserts its set is non-empty, so none can pass vacuously.
