## 3. Integration Architecture

```text
--question ──► parse_args ──► load_corpus ──► Retriever(chunks) ──► retrieve
                                                                       │
                                                              RetrievalResult
                                                                       │
                                                     Generator() ──► generate
                                                                       │
                                                             GenerationResult
                                                                       │
                                                                  serialize
                                                                       │
                                                            sys.stdout.write ──► exit 0
```

`scripts/cli.py`, placed there because the dependency direction is `scripts/` → `sample_rag/` and `docs/architecture.md` §6 bars the reverse — the CLI needs `load_corpus`, which lives in `scripts/`, so a CLI inside `sample_rag/` would have to import `scripts/`.

**Nothing is re-implemented.** `load_corpus` and `DEFAULT_FILTERS` are `scripts/run_retrieval.py`'s own, so the CLI cannot disagree with the retrieval runtime about what the corpus is or how retrieval is parameterized; the corpus is loaded through the same `validate_chunks(load_chunks())` gate every consumer uses. `serialize` is `sample_rag/generator.py`'s, so the CLI chooses no representation of its own.

### Orchestration Traceability Rule

`main()` contains eight executable statements, each exactly one permitted category:

| Statement | Category |
|---|---|
| `arguments = parse_args(argv)` | argument parsing |
| `chunks = load_corpus()` | runtime component invocation |
| `retriever = Retriever(chunks)` | runtime component construction |
| `retrieval = retriever.retrieve(...)` | runtime component invocation |
| `generator = Generator()` | runtime component construction |
| `generation = generator.generate(...)` | runtime component invocation |
| `serialized = serialize(generation)` | serialization |
| `sys.stdout.write(serialized)` | stdout emission |
| `return 0` / `sys.exit(main())` | process exit |

`parse_args()` contains three statements, all argument parsing. **No statement was unclassifiable, so no STOP condition arose.**

This is enforced executably, not asserted: `test_every_statement_is_orchestration` walks the AST and requires every statement to be a call, an assignment binding a call, or a return — **and** every callee to be in an enumerated approved set, so a computation expressed as `len(result.statements)` is refused rather than passing as "an assignment binding a call".

## 4. Runtime Boundary Preservation

The CLI imports exactly `argparse`, `sys`, `sample_rag.generator`, `sample_rag.retriever`, `scripts.run_retrieval` — enforced by an allowlist, which fails on any import nobody thought to forbid.

Not reachable, each named individually so a failure says which boundary was crossed: Knowledge Manifest (`build_manifest`), Chunk Corpus builder (`build_chunks`), Evidence Trace Dataset (`build_evidence_trace`), Retrieval Evaluation, Retrieval Metrics, Retrieval Diagnosis, `evaluation.*`, and `KnowledgeSource`. Those authorities remain validation-only.

`docs/GENERATION_CONTRACT.md` §18 records why this matters rather than being bureaucratic: every barred artifact exists for the repository's own 22 benchmark questions, so a runtime path that reads one serves those 22 and nothing else while appearing to work. The CLI answers an arbitrary question typed at a terminal.

## 5. Identity Preservation

Work Package 4's requirement is about **object identity**, which bytes cannot demonstrate: a CLI that reconstructed a field-identical `GenerationResult` would produce identical output while having defined a runtime artifact of its own. Frozen dataclasses compare by value, so an equality check would pass.

Two specifications therefore run the pipeline **in-process** with each component subclassed and delegating — nothing stubbed, the real pipeline executed, only identities observed:

| Seam | Assertion |
|---|---|
| `generate` → `serialize` | `captured["serialized"] is captured["generated"]` |
| `retrieve` → `generate` | `captured["received_retrieval"] is captured["retrieved"]` |

Backed structurally by `test_the_cli_constructs_no_runtime_artifact`, which asserts the module never calls `GenerationResult`, `GeneratedStatement`, `SupportingEvidence` or `RetrievalResult`. The CLI does not flatten, re-order, filter, augment, clone, reconstruct or wrap any runtime artifact — it holds references and passes them on.

## 6. Deterministic Guarantees

| Guarantee | Mechanism | Specification |
|---|---|---|
| stdout == `serialize(result)` byte-for-byte | The serialized string is written and nothing else | `test_stdout_equals_the_serialized_generation_result` |
| Exactly one trailing newline | `sys.stdout.write`, **not** `print` | `test_stdout_carries_exactly_one_trailing_newline` |
| No banner, timestamp, colour, progress, elapsed time, completion message | Nothing else is written | `test_stdout_is_exactly_one_json_document`, `test_stderr_is_silent_on_successful_execution` |
| Repeated execution byte-identical | Determinism inherited from components; the CLI adds nothing | `test_repeated_execution_produces_byte_identical_stdout` (separate processes) |
| Exit 0 on success | `return 0` | `test_main_returns_zero_on_successful_execution` |
| Exit 2 on invalid arguments, stderr only | argparse's own convention, not re-implemented | `test_a_missing_question_exits_two_and_reports_only_to_stderr` |

`sys.stdout.write` over `print` is the single most consequential line in the module: `print` would append a second newline to a string §13.2 already terminates with exactly one, and the byte-identity guarantee would be lost to a formatting convenience. A mutant making that substitution is killed by two specifications.

Determinism is **inherited, not added**: the retriever is a fixed function of query and corpus, the generator constructs no varying value (`docs/GENERATION_CONTRACT.md` §12), and the CLI computes nothing. The repeated-execution specification uses separate processes, so it also covers hash randomization and import-time ordering that a single process cannot show.

## 7. Validation Summary

**27 specifications** in `tests/test_cli.py`. Suite total **372 passed** (345 baseline, +27, 0 removed, 0 modified), deterministic across three runs at 2.10–2.20s.

Two mechanisms, deliberately separated: **subprocess** for real stdout bytes and exit codes — the only way to specify what a user observes — and **in-process** for object identity, which bytes cannot show. Neither alone is sufficient.

Nothing here re-specifies retrieval, generation or serialization; those belong to `tests/test_generator.py` and the retrieval families, and repeating them would be testing the components through a second front door. What is specified is what integration can get wrong: the sequence, the artifacts, the identity, the bytes, the boundary, the exit codes — and, unusually for this repository, **the shape of the code itself**.

### Mutation evidence

**25 mutants introduced, 25 killed.** Structural mutants replaced the module source; behavioural mutants were executed as real processes from the scratchpad. No repository file was modified at any point.

Coverage: derived value via `len()` · output transformation · sorting artifact contents · branch on artifact contents · extra module-level branch · reconstructed `GenerationResult` · own `json` import · f-string and `%` formatting · reordered call sequence · unapproved public helper · imports of `build_evidence_trace`, `evaluation.retrieval_metrics`, `KnowledgeSource` · `print()` double newline · emitted banner · completion message on stderr · non-zero exit on success · silently defaulted missing argument · injected timestamp.

**Two mutants initially survived, and both exposed real defects in the specifications — not in the CLI.** Both were fixed and re-verified:

1. `test_every_statement_is_orchestration` accepted any assignment binding a call, so `total = len(generation.statements)` — a computation over artifact contents, and precisely what the Orchestration Traceability Rule forbids — passed. The specification now also constrains *what may be called*, via an enumerated per-function callee allowlist. It now kills that mutant and three others (`sorted`, `.upper()`, output transformation) that the original would also have missed.

2. `test_the_cli_does_not_reach_the_evaluation_layers` scanned `cli_source().split('"""')[-1]`, intending to skip the module docstring. Because the *function* docstrings come later in the file, that expression returned only the text after the last one — excluding the entire import block. **The specification was checking almost nothing while passing.** It now reads imports from the AST, which cannot be defeated by where docstrings sit.

The second is the more instructive failure: a text-scan written to skip docstrings can silently skip the code it was meant to check. Only a mutant revealed it — review had not.

## 9. Known Limitations

Recorded, not resolved.

1. **`--question` is the entire interface.** No `--top-k`, no output-path option, no verbosity flag. `DEFAULT_FILTERS` is used as-is, so a user cannot vary retrieval depth from the command line. This is deliberate — each would be public surface no approved clause requires — but it means the CLI exposes less than the Retriever supports.

2. **Byte-identity is specified on POSIX.** `sys.stdout.write` emits `\n`; a platform translating it to `\r\n` would produce different bytes for the same run. The repository targets Linux/WSL2, and the serialization is pure ASCII (`ensure_ascii` default), so no encoding ambiguity arises there. Untested elsewhere.

3. **The corpus is reloaded on every invocation.** Each run parses and re-validates all 172 chunks. Correct and deterministic, and caching would be state the pipeline does not have — but it makes the CLI unsuited to a loop over many questions, which `scripts/run_retrieval.py` already serves.

4. **An empty `--question` is accepted.** `--question ""` is well-formed: argparse has no emptiness rule and the CLI adds none, because a non-emptiness check would be validation logic this layer may not hold. It tokenizes to nothing, retrieves nothing, and abstains through the pipeline's own contracted path. Specified rather than left undiscovered.

5. **`--help` is outside the byte-identity guarantee.** It is a usage query, not an execution, and writes argparse's own text to stdout. Work Package 5's guarantee covers successful execution; `--help` is specified separately so the observable surface is fully documented rather than partly undefined.

6. **The abstention path is reachable only by lexical disjointness.** The specification uses a query sharing no term with any chunk. That exercises the real path, but it depends on the Milestone 1A lexical retriever; a Milestone 2 semantic retriever may return chunks for the same query, at which point that specification would exercise the Answer path instead. It would still pass — it asserts conformance, not a particular outcome — but the abstention coverage would need revisiting.

## 10. Observations

Observations only, per Work Package 8. Nothing below was implemented.

1. **Structural specification turned out to be the right instrument for a composition layer.** Behavioural tests can only observe that output was correct; they cannot see that a branch was added. Six of the 27 specifications read the CLI's AST, and they are what make "contains no business logic" a checked property rather than a review opinion — the mutants that added `len()`, `sorted()`, a branch and an f-string were all killed structurally, before any output-level test would have noticed.

2. **The most valuable mutant found a defect in a test, not in the code.** The docstring-splitting authority check was passing while inspecting none of the imports it was written to inspect. This is the second consecutive sprint in which mutation testing found a hole in a specification rather than in an implementation (P3.5.2 found the `created_at` marker gap), which suggests the technique is earning its cost on the validation layer specifically.

3. **Identity preservation is only observable in-process.** The requirement that the generated object *be* the serialized object cannot be established from bytes at all, since a faithful reconstruction serializes identically. This is the first specification in the repository that must run the pipeline in-process for a reason other than speed.

4. **The Milestone 1A pipeline is now runnable end to end.** `python -m scripts.cli --question "…"` executes Knowledge → Chunk Corpus → Retriever → Generator and emits a fully traceable `GenerationResult`: every statement carries the chunk id, document id and document-frame offsets of the evidence it quotes. The evidence chain the Generation Contract froze is now observable from a terminal.

5. **`docs/architecture.md` §5's `Generator.generate(prompt: Prompt)` remains the Milestone 2 target.** The CLI wires `retrieve → generate` directly, per the approved §6.2 signature. When a Context Builder exists, the change is confined to one statement in `main` — which is a consequence of the CLI holding no logic of its own, and is recorded here rather than acted on.
