## 3. Actual runtime execution path

Traced by reading the code, not the docs. The executing path is `scripts/run_generation.py`:

```text
question (--question)
    │
    ├── load_corpus()                     scripts/run_retrieval.py      → chunks
    ├── load_canonical_documents()        scripts/run_retrieval.py      → canonical ids
    └── canonical_order(chunks, ids)      scripts/run_hybrid_retrieval  → total tie-break order
    │
    ├── semantic_route(runtime, q)        → list[str]  ranked chunk ids   (BGE → FAISS)
    ├── lexical_route(retriever, q)       → list[str]  ranked chunk ids   (BM25)
    └── fuse_routes(sem, lex, order)      → list[str]  fused ids, top_k   (RRF)
    │
    ├── ContextBuilder.resolve(fused)     → chunk records, order preserved positionally
    └── ContextBuilder.assemble(…, q)     → Prompt(query, context, chunk_ids, provenance)
    │
    └── ModelGenerator.generate(prompt)   → GenerationResult(answer_text, outcome,
                                                             statements, diagnostics)
            └── DeepSeekClient.complete() → the one sanctioned provider interaction
```

**What each boundary actually returns — established by reading the functions:**

| Boundary | Returns | Consequence for the trace |
|---|---|---|
| `semantic_route` | `list[str]` — ranked ids, **no scores** | Semantic **rank** is position. Semantic **score** does not exist here and is not obtainable — `VectorStore.query` is `-> list[str]` by `docs/architecture.md` §7 |
| `lexical_route` | `list[str]` from `RetrievalResult.diagnostics["retrieved_chunk_ids"]` | Lexical (BM25) **rank** is position |
| `fuse_routes` → `reciprocal_rank_fusion` | `list[str]`, truncated to `top_k` | Fused **rank** is position. The **RRF score is computed and discarded** at this boundary |
| `fusion.rank_candidates` | `list[(chunk_id, score)]` over the **full union**, untruncated | The scored union — the same call `reciprocal_rank_fusion` makes internally |
| `ContextBuilder.assemble` | `Prompt(query, context, chunk_ids, provenance)` | `chunk_ids` is the fused order positionally; `provenance` is parallel to it, four fields, **no chunk text** |
| `ModelGenerator.generate` | `GenerationResult` | `diagnostics` is exactly `{query, retrieval_route, stub}` |
| `ModelGenerator._statements` | one statement per assembled chunk, one span each, in provenance order | Evidence is **1:1 with provenance** under M2-06 — see §10 |
| `DeepSeekClient` | `.model` property; `.endpoint` property; no credential accessor | Model is observable; the key is unreachable by construction |
| `scripts/run_generation.py` | `time.perf_counter()` around `generate()` | Generation latency is **already measured on the path** |

**Two things the path does not have, established by search rather than assumed:**

1. **No wall-clock/timestamp convention exists anywhere in `sample_rag/` or `scripts/`** — `grep` for `datetime`, `utcnow`, `isoformat`, `timezone.utc` returns nothing. See §9.
2. **No retrieval-stage or assembly-stage timing exists.** Only generation is timed. See §9.

## 4. Proposed schema (recorded before implementation)

The proposal below was fixed **before** any implementation file was modified, from the runtime inspection in §3 — not from RO-15's authorized list, which is a capability boundary and not a schema.

Classification rule applied to every candidate, in RO-15 Decision 6's terms:

```text
PERSIST    evidence that cannot otherwise be recovered once the process exits
REFERENCE  evidence deterministically recoverable from committed corpus + provenance
OMIT       evidence the runtime does not expose, or that another persisted field already carries
```

| Candidate (RO-15 D-5 authorized list) | Runtime source | Class | Reason |
|---|---|---|---|
| execution identity | **none** | **OMIT** | No identity convention exists; a synthetic id is a label, not evidence |
| timestamp | **none** | **OMIT** | No clock convention exists. Inventing one is barred |
| query | `Prompt.query` | **PERSIST** | The request; not recoverable afterwards |
| retrieval candidate union | `fusion.rank_candidates` | **PERSIST** | Query-derived; gone at exit |
| semantic rank | position in `semantic_route` output | **PERSIST** | Query-derived |
| BM25 rank | position in `lexical_route` output | **PERSIST** | Query-derived |
| RRF rank | position in scored union | **PERSIST** | Query-derived |
| RRF score | `rank_candidates` `(id, score)` | **PERSIST** | Query-derived; `RRF_SCORE_PRECISION` exists for exactly this consumer |
| source-leg attribution | membership in the two ranked lists | **PERSIST** | The route a candidate entered through — §10 |
| selected chunk ids | `Prompt.chunk_ids` | **REFERENCE** | Identical to the `chunk_id` sequence of `provenance`; persisting both duplicates |
| `Prompt` provenance | `Prompt.provenance` | **PERSIST** | The four-field record; carries the selected ids |
| `Prompt.context` | `Prompt.context` | **OMIT** | Corpus text; recoverable from chunk ids + offsets (§24.4's own claim) |
| generation component | `type(generator).__name__` | **PERSIST** | Observed, not asserted — RO-14 identity |
| generation contract version | trace-layer table, RO-14 | **PERSIST** | Governance identity owned at the observation boundary (D-7) |
| provider | `type(client).__name__` | **PERSIST** | Observed |
| model | `client.model` | **PERSIST** | Observed; not recoverable afterwards |
| generation outcome | `GenerationResult.outcome` | **PERSIST** | One short enum; the execution's classification |
| `answer_text` | `GenerationResult.answer_text` | **PERSIST** | **G-9 does not guarantee reproducibility** — D-6 |
| supporting-evidence references | `statements[].supporting_evidence` | **REFERENCE** | Chunk ids only; offsets and text recoverable via provenance + corpus |
| `SupportingEvidence.text` | same | **OMIT** | Corpus text duplication — D-6 |
| `GeneratedStatement.text` | same | **OMIT** | Equal to the evidence span text; same duplication |

| `GenerationResult.diagnostics` | `{query, retrieval_route, stub}` | **OMIT** | Fully covered by fields already persisted |
| provider endpoint | `client.endpoint` | **OMIT** | Not in the authorized list; carries no diagnostic value the model/provider pair lacks |
| semantic similarity score | **does not exist at the boundary** | **OMIT** | RO-15 D-5 bars it and the `VectorStore` boundary stays closed |

## 5. Final schema

One completed execution = one JSON object = one JSONL record.

```json
{
  "query": "string",
  "retrieval": {
    "route": "RRF",
    "top_k": 5,
    "candidates": [
      {
        "chunk_id": "string",
        "source_legs": ["LEXICAL", "SEMANTIC"],
        "semantic_rank": 2,
        "lexical_rank": 1,
        "rrf_rank": 1,
        "rrf_score": 0.032523
      }
    ]
  },
  "assembly": {
    "provenance": [
      {
        "chunk_id": "string",
        "document_id": "string",
        "character_start": 0,
        "character_end": 42
      }
    ]
  },
  "generation": {
    "component": "ModelGenerator",
    "contract_version": "2.0.0",
    "provider": "DeepSeekClient",
    "model": "deepseek-v4-flash",
    "outcome": "Answer",
    "answer_text": "string",
    "statement_evidence_chunk_ids": [["string"]],
    "latency_ms": 1234.5
  }
}
```

**Field notes.**

- `retrieval.candidates` covers the **whole union** of both routes, not only the selected chunks — a candidate that lost is exactly the diagnostic evidence a selected-only record cannot carry.
- `semantic_rank` / `lexical_rank` are **`null`** when that route did not supply the candidate. Absence is recorded as absence, never as `0` and never as a sentinel rank.
- `lexical_rank` is RO-15's *"BM25 rank"* under the repository's own route name — the `LEXICAL` route **is** BM25 (`sample_rag/retriever.py`), and `scripts/run_hybrid_retrieval.py` already fixes `LEXICAL_ROUTE = "LEXICAL"`. No second vocabulary is introduced.
- `assembly.provenance` carries the selected chunk ids: `provenance[i].chunk_id` **is** `Prompt.chunk_ids[i]`. One structure rather than two is what makes them unable to contradict each other (§15).
- `statement_evidence_chunk_ids[i]` is the chunk ids statement *i* cites. Offsets, `document_id` and span text are all recoverable through `assembly.provenance` and the committed corpus.
- `latency_ms` covers `ModelGenerator.generate` **including** the provider interaction, and nothing else. Retrieval and assembly are not timed — see §9.

## 7. Why each persisted field exists

**Everything above is query-derived and ceases to exist when the process exits.** That is the whole test applied — RO-15 Decision 6's *"persist evidence that cannot otherwise be recovered."*

- **`query`** — the request the run answered. Without it no other field can be interpreted.
- **The candidate union with per-route ranks and `source_legs`** — this is the diagnostic core, and the reason a selected-chunks-only record would be worth much less. It answers *which route supplied this candidate*, *where each route placed it*, and *what fusion did with that*. The §21 example shows the case that matters: `c1` ranked **2nd** semantically and **1st** lexically, and RRF promoted it to **1st** overall because both routes agreed — a rank movement no other artifact in the repository records.
- **`rrf_score`** — a ranking is only explainable against the numbers that produced it, which is `sample_rag/fusion.py`'s own stated reason for exposing `rank_candidates` separately from `reciprocal_rank_fusion`. `RRF_SCORE_PRECISION` exists, in that module's words, *"so a diagnostic record can print a score without a caller inventing a format"* — this is that record.
- **`assembly.provenance`** — which chunks reached prompt construction, in what order, and where in their documents they came from. Also the join key back to the committed corpus for everything referenced rather than persisted.
- **`component` + `contract_version`** — RO-14 established two generation components across two contract eras; without these a trace could not be read unambiguously as to which one ran.
- **`provider` + `model`** — the model is a runtime selection and is not recoverable from the corpus.
- **`outcome`** — the execution's own classification, one short enum.
- **`answer_text`** — **the single field with a formal reason it must be persisted.** §24.3's G-9 split expressly declines to guarantee model-output reproducibility, so re-running cannot recover it.
- **`statement_evidence_chunk_ids`** — the attribution structure: which chunk each statement cites. Records the linkage while duplicating none of the payload.
- **`latency_ms`** — already measured on the path.

## 10. Source-leg and rank attribution behaviour

**`source_legs` is the route a candidate entered the fusion path through** — taken from membership in the ranked list that route actually returned for *this query*. It is **not** the chunk's document, file type, corpus or category, and a chunk is never labelled `SEMANTIC` merely because the semantic index contains it: every corpus chunk does, so such a label would attribute nothing. A candidate both routes returned carries **both** legs, which is exactly the case RRF sums two contributions over.

**Rank is position**, 1-based, read back out of each route's returned sequence — the same thing `sample_rag/fusion.py` `positional_ranks` reads, and the only thing RRF reads from a route. This is not a re-derivation of the ranking; it is the ranking.

**A route that did not supply a candidate records `null`, never `0`.** Absence is not a rank.

**On the second `rank_candidates` call.** `reciprocal_rank_fusion` computes RRF scores and discards them, returning ids only. The scores are read by calling `rank_candidates` — the function `reciprocal_rank_fusion` itself calls, on identical arguments — beside it. Both are pure functions of the same inputs, so they cannot disagree; **but that is asserted rather than assumed.** `retrieval_evidence` raises `TraceIntegrityError` if the executed selection is ever not the leading order of the scored union, and `fuse_routes` remains the sole authority for which chunks were selected. Specification: `test_m218_a_selection_that_is_not_the_scored_order_is_refused`.

**One observed limitation:** `lexical_rank` is RO-15's *"BM25 rank"* under the repository's own route name. The `LEXICAL` route **is** BM25 (`sample_rag/retriever.py`), and `LEXICAL_ROUTE = "LEXICAL"` is fixed by `scripts/run_hybrid_retrieval.py`. No second vocabulary was introduced.

## 11. JSONL storage behaviour

**One completed execution = one JSON object = one line.** Appended, never rewritten: earlier records are evidence of earlier executions.

`json.dumps(trace, ensure_ascii=False) + "\n"`, UTF-8, insertion-order keys. **This is deliberately not `docs/GENERATION_CONTRACT.md` §13.2's form** — §13.2 fixes `indent=2`, which spans many lines and which JSONL cannot carry. That divergence is the concrete consequence of **RO-15 Decision 4**: the two forms differ because the two artifacts differ, and **§13.2 remains in force, unamended, for the `GenerationResult` it governs.** Specification: `test_m218_the_trace_form_is_not_the_generation_contract_serialization_form`.

Location: **`scripts/execution_trace/executions.jsonl`** (`TRACE_ROOT / TRACE_FILENAME`). Every function takes its destination as an argument, which is what lets the whole specification suite write to `tmp_path` and never touch the runtime directory.

**Not implemented, because RO-15 leaves them to this sprint and the simplest repository-native choice was taken:** no locking, no rotation, no retention policy, no cross-process coordination. See §22 F-2.

## 13. Credential safety — absolute

**The trace layer cannot read a credential.** It imports exactly `json`, `pathlib` and `sample_rag.fusion` — asserted, not described — and references no `os`, `environ` or `getenv`. `DeepSeekClient` reads `DEEPSEEK_API_KEY` inside `complete` and exposes no accessor, so the trace layer is handed an object from which no secret is reachable. **Credential absence is structural here, not a promise about a code path.**

Specifications: `test_m218_no_credential_reaches_a_trace` (sets a sentinel key in the environment and asserts it appears nowhere in the serialized record), `test_m218_the_trace_layer_never_reads_the_environment`, `test_m218_no_authorization_or_header_material_is_recorded`, `test_m218_no_raw_provider_payload_is_recorded`.

## 14. Content-sensitivity handling

**Distinct from credential safety, and treated as such.** `query`, `answer_text` and the recorded chunk/document ids may reference resume and job-corpus material, which makes a trace **potentially sensitive derived data even though it holds no credential**.

The response is **minimal persistence**, not machinery:

- `Prompt.context` is never persisted — the largest body of corpus text on the path.
- `SupportingEvidence.text` and `GeneratedStatement.text` are never persisted.
- Chunks and documents appear as **ids and offsets**, not as text.
- The two content-bearing fields that remain — `query` and `answer_text` — are each irrecoverable execution evidence, and `answer_text` has the formal G-9 reason in §7.
- `scripts/run_generation.py` prints the trace **path**, not its contents.

**No redaction, anonymization, encryption, external storage, database retention or telemetry was introduced** — RO-15 D-8 places all of those outside this ruling.

## 15. Trace-integrity guarantees

Three relationships are checked **before a record exists**, and a violation raises `TraceIntegrityError` rather than being written down. A diagnostic artifact whose references dangle is worse than none, because it looks checkable.

| Guarantee | Where enforced |
|---|---|
| The executed selection is the leading order of the scored candidate union | `retrieval_evidence` |
| `Prompt.provenance` corresponds to `Prompt.chunk_ids` | `assembly_evidence` |
| Every assembled chunk appears among the retrieval candidates | `build_trace` |
| Every cited chunk appears in the assembled prompt | `build_trace` |

**A fourth relationship is guaranteed by construction rather than checked:** selected chunk ids and `Prompt` provenance are **one structure**, not two, so they cannot come to disagree. That was the reason for referencing the ids through provenance instead of listing them twice.

Each guarantee has a specification asserting the refusal, not merely the happy path.

## 22. Remaining limitations and findings

**M2.18-F-1 — no temporal or execution identity is recorded, because the repository has no convention for either.** No `datetime`, `utcnow`, `isoformat` or `timezone.utc` reference exists anywhere in `sample_rag/` or `scripts/`, so a wall-clock timestamp would have required introducing a clock contract, and a synthetic execution id would have been a generated label rather than evidence. Both were **omitted rather than invented**, and both are specified as absent so the omission cannot be undone silently. **Consequence:** records are distinguished by append order and by `query`; two runs of the same question are not distinguishable from the record alone. **Non-blocking.** Adding either is a Repository Owner decision about repository convention, not an implementation gap this sprint may fill.

**M2.18-F-2 — no concurrency, rotation or retention behaviour exists.** RO-15 leaves all three to this sprint, and the simplest repository-native choice was taken: one append of one line per completed execution, no lock, no rotation, no retention policy. `scripts/run_generation.py` performs one execution per invocation, so the repository does not currently produce a concurrent writer. **Non-blocking**, and deliberately not solved speculatively.

**M2.18-F-3 — the trace records only the model-backed path.** `scripts/cli.py` (`Generator`, v1.0.0) is not traced, and `CONTRACT_VERSIONS` deliberately contains no v1.0.0 entry, because tracing the Milestone 1A path would change frozen Milestone 1A behaviour, which RO-15 does not authorize. **Non-blocking** and intended.

**M2.18-F-4 — statement-to-evidence attribution is 1:1 because M2.06-F-1 makes it so.** `ModelGenerator._statements` emits one statement per assembled chunk with one span each, since DeepSeek supplies no citation mechanism. The recorded `statement_evidence_chunk_ids` therefore currently mirrors the provenance order. **The trace records the linkage rather than assuming it**, so a future generator that attributes differently would show that difference without any change here. **This sprint does not resolve M2.06-F-1, and does not claim to** — it makes the finding's consequence visible, and **observability is not repair** (RO-15 D-11).

**Open synchronization item, owned by the Repository Owner, not by this sprint.** The **M2-18** register row still reads *"OPEN — ALLOCATED, NOT IMPLEMENTED"*, which the second clause of has been overtaken by this sprint. Under **RO-10 Decision 2** and §1.3 this sprint may not edit that row — it discharges nothing and was explicitly barred from discharging M2-18. **M2-18 remains OPEN.**

**No authority conflict was encountered.** No frozen contract required changing, no `VectorStore` widening was needed, no semantic similarity score was reachable or wanted, no dependency was required, and every field RO-15 authorized either existed at an existing boundary or was omitted and recorded above.
