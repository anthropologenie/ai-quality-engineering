  Sprint P3.1.7 — Independent Implementation Review

  Knowledge Layer

  ---
  1. Executive Summary

  The runtime implementation is sound. Document and KnowledgeSource faithfully implement the approved contracts: identity is read and never derived,
  determinism holds across processes, the failure surface is single and complete, and no repository mutation occurs. Reviewed on its own evidence,
  the code would pass.

  The assurance around it does not hold up. Three things fail independent scrutiny:

  1. The Executable Specification Suite does not protect the Knowledge Layer's actual output. Independent mutation testing (18 semantically
  meaningful mutations, generated for this review — the repository contains none) killed 12 and left 6 alive. One surviving mutant reduces
  Document.text for the entire corpus from 10,591 characters to the empty string, and all 77 specifications still pass. Line coverage is 99%; that
  number is misleading.
  2. F-2 is confirmed reproducible and was deferred to this sprint for a ruling. A manifest source of ../… or an absolute path loads a file from
  outside the corpus root and returns its contents as Document.text. This review rules on it below.
  3. docs/P3.1.5_Construction_Validation_Evidence_Report.md — a Review Scope artifact — is textually corrupted at HEAD, with dropped character runs
  inside its own findings and recommendations sections.

  Verdict: CHANGES REQUESTED, scoped to three narrow, cheap items. No architectural rework, no contract change, and no runtime redesign is required.

  Why M15 is the serious one

  w:t elements sit inside w:r runs, so findall (direct children only) matches nothing. Measured directly:

  BASELINE       len(text)= 10591   blank-line blocks= 86
  M15 (findall)  len(text)=     0   text = ''

  The sole corpus document's text becomes empty, and 77/77 specifications pass. Every content-shaped assertion is satisfied vacuously by "":
  test_a14 (isinstance ✓), test_a7 (✓), test_b5 (normalize_text("") == "" ✓), test_b7 (no \r ✓, no trailing whitespace ✓, no \n\n\n ✓, "" ==
  "".strip() ✓), test_b2 (both runs equally empty ✓). test_a13 checks id is non-empty; nothing checks text.

  This is not a contrived path. The extract_docx_paragraphs docstring itself notes that text-carrying constructs (w:tab, w:br, footnotes, text
  boxes) are uninterpreted and that a corpus gaining them "would reopen extraction fidelity" — i.e. the module anticipates exactly the class of
  change that would silently empty or truncate output.

  Why M01 matters

  Measured: "\n\n" → 86 blank-line-separated blocks; "\n" → 1 block of 10,506 characters. This is precisely the regression the implementation's own
  docstring says rule N1 exists to prevent ("collapsing it to one 10.5k span and making that fallback the only path ever taken"). No specification
  protects it.

  Coverage gaps behind the survivors

  - No synthetic .docx success specification exists. SyntheticCorpus.docx() (conftest.py:150-153) is never called — only docx_package() is, and only
  by failure-mode constructors. Every .docx success path runs through the one real resume, and nothing asserts what comes out.
  - .md is never exercised despite being in SUPPORTED_EXTENSIONS.
  - No uppercase-extension case, despite .suffix.lower() being deliberate.
  - N2 is specified only as a normalize_text unit, never end-to-end through extract_text on a CRLF file — which is why M10 survives.
  - Empty-text legality is specified only via direct Document(id=…, text="") construction, never through load() — which is why M17 survives.

  Redundancy (minor, and defensible)

  test_case_b_manifest_entry_without_a_corpus_file_raises and the missing-corpus-item failure mode reach the same code path. The docstring pre-empts
  this and argues they encode different claims (the disagreement asymmetry vs. the failure surface). Accepted as deliberate, not accidental
  duplication.

  6. Architecture Review

  Boundaries hold. sample_rag/ takes no dependency on scripts/ (verified: no import). The S1 identity strategy is implemented as documented — the
  Manifest, not the filesystem, is the corpus enumeration, and there is no rglob/iterdir/glob/walk call anywhere in the module, making the Case A
  narrowing structural rather than incidental. Construction performs no validation component role, writes nothing, and does not touch
  documents[].indexed. Document owns no behaviour. The frozen interface KnowledgeSource.load() -> List[Document] is unchanged.

  Two boundary findings.

  Duplicated admissibility gate. SUPPORTED_EXTENSIONS = {".docx", ".md", ".txt"} exists twice — scripts/build_manifest.py:27 and
  sample_rag/knowledge_source.py:47. The in-code comment justifies the copy by the architecture.md §6 boundary, which is legitimate reasoning. But
  Construction Plan §9.1 rejected strategy S3 on exactly this ground — "two implementations must be changed together, with nothing enforcing it —
  High drift risk." That accepted risk was reasoned about for identity and then re-incurred for admissibility without appearing in the Decision
  Register, and no specification asserts the two sets agree. Widening build_manifest.py's set alone would produce manifest entries that construction
  rejects, with nothing detecting it.

  Corpus containment is stated but not enforced (F-2). Independently reproduced at HEAD:

  F-2 absolute path : LOADED  id='x' text='SECRET CONTENT OUTSIDE THE CORPUS'
  F-2 relative '..' : LOADED  source='../outside_secret.txt' text='SECRET CONTENT OUTSIDE THE CORPUS'

  resolve_source_path (knowledge_source.py:127) is SAMPLE_RAG_ROOT / Path(source); pathlib lets an absolute operand discard the root, and no
  containment check follows. Construction Plan §4.1 defines DOCUMENTS_ROOT as determining "which filesystem items are corpus items at all" — the
  implementation does not enforce that boundary.

  Ruling (F-2 was deferred to this sprint): the boundary belongs at construction time. It is a two-line assertion in resolve_source_path, it
  enforces a boundary the plan already states, and deferring it to P3.1.8 misroutes a structural constraint into a cross-artifact validation layer —
  a category error against the contract's own §8.5 division. See A-2.

  Contract stability: the Document Contract has not drifted. Chunker._validate_document's duck-typed .id/.text expectation remains exactly
  satisfied, as §14.1 predicted.

  9. Findings Register

  Implementation Findings

  I-1 · Specification suite does not constrain Document.text content · MAJOR
  Evidence: Mutation M15 (paragraph.iter(w:t) → findall) reduces the corpus document's text from 10,591 chars to ''; 77/77 specifications pass.
  Every content assertion is vacuously satisfied by the empty string (test_a14, test_b5, test_b7, test_b2). Coverage 99% (1 miss) conceals this
  entirely.
  Impact: A plausible regression in .docx traversal — the exact class the module docstring flags as unresolved — silently empties the Knowledge
  Layer's only output. P3.1.8 and the Chunk Layer would build on it undetected.
  Recommendation: Add a synthetic-.docx round-trip specification (SyntheticCorpus.docx() already exists and is unused) asserting extracted content,
  plus a real-corpus non-vacuity assertion.
  Disposition: Required before P3.1.8.

  I-2 · Normalization rule N1 (paragraph separator) is unprotected · MAJOR
  Evidence: Mutation M01 ("\n\n" → "\n") survives; measured 86 blank-line blocks → 1 block of 10,506 chars — the precise failure normalize_text's
  docstring cites as the reason the rule exists.
  Impact: Silently makes the Chunker's recursive-character fallback the only path taken, contradicting MILESTONE_1A.md build item 3 ("never the
  default path").
  Recommendation: Extend B8's parametrized table with an N1 case over a multi-paragraph synthetic .docx.
  Disposition: Required before P3.1.8.

  I-3 · Unreachable defensive guard · MINOR
  Evidence: sample_rag/knowledge_source.py:278-281. normalize_text returns str.strip() — always str. Line 279 is the module's only uncovered line;
  mutation M16 (deletion) survives.
  Impact: Dead code presenting as a safety check; misleads future maintainers about what is actually guarded.
  Recommendation: Remove, or relocate the check to the extraction boundary where it is reachable. Record the choice.
  Disposition: Observation-level; fold into the next construction-touching sprint.

  I-4 · .docx success path, .md, and case-insensitivity are unspecified · MINOR
  Evidence: SyntheticCorpus.docx() (conftest.py:150) is never called; grep finds no .md fixture and no uppercase-extension case; M10 and M14
  survive.
  Impact: Two of three supported extensions and the whole successful extraction path rest on one real file.
  Recommendation: Add per-extension construction specifications.
  Disposition: Recommended.

  I-5 · Empty-text legality unspecified through load() · MINOR
  Evidence: Mutation M17 (reject empty text in load()) survives. test_a14 covers only direct Document construction.
  Impact: Contract invariant 2 / A7 could be broken at the construction boundary undetected.
  Recommendation: Specify an empty-source-file corpus item producing a legal Document.
  Disposition: Recommended.

  I-6 · test_b6 hardcodes a corpus filename · OBSERVATION
  Evidence: test_knowledge_source_construction.py:95 — literal "documents/resume/Karthik_SR_Resume_v2_2.docx".
  Impact: Corpus expansion or rename breaks a specification about normalization purity, unrelated to that file.
  Recommendation: Derive the path from the manifest fixture.

  I-7 · test_a15 allowlist tracks CPython internals · OBSERVATION
  Evidence: Allowlist includes __firstlineno__/__static_attributes__ (3.13+); suite runs on 3.12.
  Impact: A future CPython synthesizing a new dataclass member fails this specification for a non-repository reason.
  Recommendation: Assert on callables the module declares rather than differencing vars().

  Architecture Findings

  A-1 · SUPPORTED_EXTENSIONS duplicated across the sample_rag/↔scripts/ boundary · MAJOR
  Evidence: scripts/build_manifest.py:27 and sample_rag/knowledge_source.py:47, identical literals. Construction Plan §9.1 rated this duplication
  pattern "High" drift risk when rejecting strategy S3. Not present in the §15 Decision Register. No specification asserts equality.
  Impact: Widening the builder's gate alone produces manifest entries construction rejects — a corpus/manifest inconsistency with no detector, and
  no recorded decision explaining the accepted trade-off.
  Recommendation: Record the accepted duplication as an explicit decision, and add a specification asserting the two sets are equal (a
  cross-boundary assertion, not an import — it does not violate §6).
  Disposition: Record now; specification recommended.

  A-2 · Corpus-root containment is stated but not enforced (F-2) · MAJOR
  Evidence: Reproduced at HEAD — absolute and ../ sources both load files from outside sample_rag/ and return their contents as Document.text.
  knowledge_source.py:127. Construction Plan §4.1 states the boundary.
  Impact: A structural boundary the plan declares is unenforced. Exploitation requires write access to a tracked file, so severity is bounded — but
  a corpus boundary that only holds by convention is not a boundary.
  Recommendation: Enforce containment in resolve_source_path (resolve and assert the result is relative to SAMPLE_RAG_ROOT), raising
  DocumentConstructionError. Add the corresponding specification.
  Disposition: F-2 ruled construction-scoped. Required before P3.1.8 — or, if the repository disagrees with this ruling, an explicit recorded
  rejection.

  A-3 · Admissibility checking partially shadows validate_manifest · MINOR
  Evidence: discover_manifest_entries (:104-113) type-checks id/source. The docstring bounds it — "must not grow into a second implementation of
  validate_manifest" — but nothing enforces the bound.
  Impact: Responsibility creep risk across sprints.
  Recommendation: Carry the constraint into the traceability register so it is inspectable outside the source file.

  A-4 · No injection seam for the corpus root · OBSERVATION
  Evidence: Module globals are the only configuration surface; all synthetic specifications monkeypatch them (conftest.py:115-116).
  Impact: Tests couple to module internals; parallel or nested corpora are not expressible.
  Recommendation: Record as a known constraint. No change warranted on present evidence.
