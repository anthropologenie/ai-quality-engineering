## 3. Generator Implementation

`sample_rag/generator.py` — the location `docs/architecture.md` §6 had already allocated.

```text
query + RetrievalResult ──► Generator.generate ──► GenerationResult
                                    │
                                    ├── _statement(chunk)  → GeneratedStatement + SupportingEvidence
                                    └── _assemble(...)     → answer_text

GenerationResult ──► serialize() ──► §13.2 byte form   (separate concern, §13)
```

Stateless: unlike `Retriever`, which binds to a chunk collection, the Generator holds nothing between calls, so two calls with equal arguments cannot differ and no call can observe another.

No `Prompt`, no Context Builder, no Assemble stage, no inference, no additional public method, no additional runtime responsibility.

## 8. Delegated Implementation Decisions (§20.2)

Five decisions the frozen contract delegates. Each is one deterministic rule, justified against the guarantees.

### D1 — Abstention predicate
**Rule:** `outcome` is `Abstain` exactly when `retrieval.chunks` is empty.
**Justification:** §9.3 defines Abstain as *"produced when the consumed `RetrievalResult` yields no evidence the Generator can quote"*. With one span per chunk (D2), a chunk *is* quotable evidence and no chunk is none. Because `statements` and `outcome` are both decided by this single test, **G-8's biconditional is structural rather than checked** — the two cannot disagree.

### D2 — Supporting span selection
**Rule:** the span is the whole chunk — `(chunk.character_start, chunk.character_end)`, text `chunk.text`.
**Justification:** §20.2 records this as *"the simplest conforming choice"*. More importantly it is the choice under which **G-11 rests on a corpus invariant the repository already validates** (`docs/CHUNK_CONTRACT.md` §17 invariant 3) rather than on arithmetic performed here — and the runtime has no document text available to check its own slicing against. §17 invariant 9 holds with equality on both bounds; invariant 11 holds because there is exactly one span.

### D3 — `GeneratedStatement` construction
**Rule:** one statement per retrieved chunk, text = the span's text, quoted verbatim.
**Justification:** G-7 permits *"verbatim quotation and deterministic template assembly"*. Quotation with no template is the narrowest option G-7 allows, and the only one under which "supported by construction" needs no argument beyond identity — the statement *is* its evidence. One statement per chunk also means §11.1's tie-break is unreachable and §11.2's ordering is trivially total.

### D4 — `answer_text` assembly
**Rule:** statement texts joined by `STATEMENT_SEPARATOR = "\n"`, in `statements` order; on Abstain, the fixed `ABSTENTION_TEXT`.
**Justification:** §8.1 requires the assembly to contain *"no content not present in them"*. A line separator carries no claim, and no reordering, truncation, summarization or connective text is introduced. The rule is verified in two strengths: containment (holds for any conforming assembly) and exact equality (`answer_text == separator.join(statement texts)`).

### D5 — Retrieved-chunk selection policy
**Rule:** every chunk of `retrieval.chunks` is used, in retrieval rank order.
**Justification:** the Retriever has already applied its own `top_k`. Re-filtering here would be the Generator overriding a decision the retrieval contract already made, and would make §11.1's statement ordering depend on a second, undocumented cutoff.

## 9. Implementation Limitations

Recorded, not resolved.

1. **The exact-equality half of the `answer_text` assembly specification depends on the current corpus.** `answer_text == "\n".join(statement texts)` is only a *reversible* assembly while no statement text contains the separator. No committed chunk text contains a newline (verified: 0 of 172), but that is a property of the current chunker, not a contract invariant. The containment half of the specification holds unconditionally.

2. **§11.1's tie-break and §11.2's sort are unreachable under this implementation.** With one statement per chunk and one span per statement, no tie can arise and nothing needs sorting. No sort was implemented, because code no path can exercise cannot be specified; the *properties* are asserted instead, so a future multi-span implementation inherits a check rather than an assumption.

3. **The whole-chunk span makes evidence coarse.** A statement cites its entire section, not the sentence answering the query. This is conforming — G-11 and invariant 9 are satisfied — and §20.2 explicitly permits a narrower span, but it means Groundedness in the `AI_Quality_Metrics_Reference` sense would be measured against a section-sized citation when Milestone 2 begins measuring it.

4. **The two-version corpus produces near-duplicate statements.** Where retrieval returns the corresponding sections of both committed resume versions, the answer carries both quotations with distinct `document_id` values. That is correct under this contract — each statement cites the version it came from, and §21 places version preference in Canonical Document Marking — but it is visible in the assembled `answer_text`.

5. **`GenerationResult.statements` and `diagnostics` are mutable containers on a frozen dataclass.** `RetrievalResult` has the same property, and freezing is field rebinding, not deep immutability. No repository code mutates them, and `test_g14_…` covers the consumed input rather than the produced output.

6. **The Abstain path is unreachable over the committed corpus at default `top_k`.** All 22 committed questions retrieve at least one chunk, so the entire abstention path is exercised synthetically. This mirrors what P3.4.1 recorded about vacuous checks: the protection is real, but it comes from synthetic cases.

## 10. Observations

Recorded as observations only, per Work Package 8. Nothing below was implemented.

1. **Making the Infer stage reachable is now a live consequence, not a hypothetical.** `evaluation/altm_rules.py` `REACHABLE_STAGES` is still `("Knowledge", "Index", "Retrieve")`, and a `Generator` component now exists. Contract §22 Q-3 recorded this in advance and placed it outside P3.5.1 and P3.5.2; it remains outside this sprint, and the Diagnosis layer is unmodified.

2. **Two of the four Generator-attributed ALTM rules are now structurally unreachable, and that is verifiable rather than argued.** `ALTM-INFER-1` (hallucinated fact) cannot occur because every statement is a byte-for-byte quotation, checked against document text by `test_g11_…`; `ALTM-INFER-2` (false confidence on an unanswerable question) cannot occur because the abstention text makes no claim about the corpus. Both properties end at Milestone 2's DeepSeek swap, which is when the Layer 4 metrics take over.

3. **The contract's own reconciliation held under implementation.** §7.1's claim — that a Golden Dataset fact and a runtime evidence span meet at the chunk id — was written before any code existed. `test_g6_…` and `test_g11_…` now join generated evidence to the Chunk Corpus and the Document corpus, with the Generator importing neither.

4. **The delegated decisions interlock more than they appear to.** D2 (whole-chunk spans) is what lets G-11 rest on a validated corpus invariant; D3 (one statement per chunk) is what makes §11.1's tie-break and §11.2's sort unreachable; D1 (empty retrieval) is what makes G-8 structural. A different choice at D2 would have required arithmetic the runtime cannot verify against any document it is permitted to read.

5. **A specification weakness was found by mutation, not by review.** The §12 varying-value scan missed `created_at`, the very key the Knowledge Manifest contract removed. It was killed independently by the exact-key `diagnostics` check, so coverage never had a hole — but the secondary net did, and only a mutant showed it.
