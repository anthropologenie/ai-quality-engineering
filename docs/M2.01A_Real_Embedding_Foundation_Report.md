# Sprint M2.01A — Real Embedding Foundation Report

**Sprint type:** Engineering Implementation — first probabilistic capability
**Repository:** `ai-quality-engineering`
**Baseline:** commit `49b079a` — *docs(governance): resolve Repository Owner ruling identifiers and ratify vector-store election (Sprint RO-06/RO-07)*, branch `main`, working tree clean

This sprint replaces the deterministic placeholder `EmbeddingProvider` with a real implementation of **`BAAI/bge-small-en-v1.5`**, behind the interface frozen at Sprint 1B.2. It ends with a validated embedding corpus. **It does not end with a retrieval system**, and implements no vector store, no nearest-neighbour search, no BM25, no fusion, no context builder, no generation and no evaluation change.

### 1.2 The model, and its revision

| | |
|---|---|
| **Model** | `BAAI/bge-small-en-v1.5` |
| **Revision** | `5c38ec7c405ec4b44b94cc5a9bb96e735b38267a` |
| **Revision published** | 2024-02-22, and resolved from `main` at this sprint |
| **Dimension** | 384 (`1_Pooling/config.json`, `word_embedding_dimension`) |
| **Pooling** | CLS (`1_Pooling/config.json`) |

| **Max sequence length** | 512 tokens (`sentence_bert_config.json`) |
| **Runtime** | `sentence-transformers`, CPU, evaluation mode |

The model was **elected by the Repository Owner and named by every committed authority** — `docs/architecture.md` §5 (*"BGE-small-en-v1.5 (Milestone 2 default)"*) and §9, `docs/roadmap.md` §7, and register **M2-01**. No substitution was made and none was considered.

The revision is pinned in code (`EMBEDDING_MODEL_REVISION`) and passed on every load, so an execution either uses this exact checkpoint or fails. `tests/test_indexer.py::test_m201_the_elected_model_and_revision_are_pinned` freezes both the id and the revision literal — the single place this suite freezes a literal deliberately, because a model revision *is* the reproducibility contract, whereas a frozen vector would specify a snapshot.

**Why `sentence-transformers`.** No repository authority names a library, only a model. The published checkpoint *is* a Sentence-Transformers model: its `modules.json` declares Transformer → Pooling → Normalize. Loading it any other way would mean re-implementing CLS pooling and L2 normalization here and calling the result the same model. `embed` therefore passes **no** pooling or normalization argument — the checkpoint defines the semantics of "BGE-small-en-v1.5", and this repository does not redefine them.

### 1.4 Two implementation-side declarations, and why they are not interface changes

`Index.stub` and `Index.dimension` have to come from somewhere once two providers exist. `docs/architecture.md` §7 freezes `EmbeddingProvider` at a single `embed` method, and this sprint is barred from redesigning it, so the two values are declared as **class attributes on the implementations** (`placeholder`, `dimension`) and read by `Indexer` through `getattr` with safe defaults.

The Protocol gained nothing. A foreign provider that declares neither attribute still indexes — which `test_1b03_index_records_the_provider_dimension` and `test_1b03_a_replacement_provider_changes_no_calling_code` both exercise with local classes that declare only `embed`.

### 4.4 Determinism — measured, not assumed

`docs/architecture.md` §9 and `docs/DOCUMENT_CONTRACT.md` §8.8 item 1 define determinism here as *repeated construction yields equal values*. A probabilistic **representation** is not a nondeterministic **computation**; nothing in this forward pass samples.

SHA-256 over the full Index of all 259 chunks, vectors sorted by chunk id:

    8b104ed0d08754cd208eb2153b0d6e79790a46a9415889dbc1c4516bfbc52548

Reproduced identically in **three independent processes**, and unchanged under `OMP_NUM_THREADS=1` and `OMP_NUM_THREADS=4`.

**What is claimed:** byte-identical embeddings across repeated executions in this environment, at this revision, on CPU. `device="cpu"` is fixed in code rather than auto-selected, so device choice cannot silently change the arithmetic.

**What is not claimed:** bitwise identity across different CPU architectures, BLAS builds or library versions. That is a property of floating-point reduction order, not a defect introduced here, and it is why every specification states a property rather than freezing a vector. See finding **O-3**.

## 7. Engineering findings

Implementation, dependency and integration observations only. **No roadmap, governance or architectural change is recommended.**

**O-1 — No embedding artifact is persisted, and none was invented.**
The sprint brief describes embeddings as *"an additional Index Layer artifact."* They are produced as one and are **not written to disk**. No repository authority defines an index or embedding artifact: `docs/architecture.md` §6 lists none, §5 describes `Index` as the Indexer's return value, and `sample_rag/indexer.py` has recorded since Sprint 1B.2 that the Index is built on demand. Persisting 259 × 384 floats would mean defining a schema, a version and a regeneration script for a new committed artifact — the standing `ADR-0001` applied to chunks — which is artifact definition, not embedding generation, and which **M2-02** (FAISS, elected at RO-06) will need to settle on its own terms. **This is the one place the brief admits two readings, and the narrower one was taken** because preserving the repository architecture is explicitly required. If the Repository Owner intends a committed embedding artifact at 2A rather than at the FAISS sprint, that is a decision to state, and it is small work on top of what exists.

**O-2 — Embedding-quality validation is deliberately absent, and belongs to a plan this sprint may not edit.**
DQ-7 validates *coverage*, and `docs/MILESTONE_1A.md` build item 2 is explicit that it *"validates indexing completeness rather than real embedding quality."* Defining a corpus-scoped embedding-quality check would require a new class in `docs/DATA_QUALITY_VALIDATION_PLAN.md`, a planning document this sprint is barred from modifying. Component-level semantic properties are therefore specified in `tests/test_indexer.py`, where the seam's specification family already lives, and the committed corpus is validated for coverage and width only. Retrieval quality is **M2-07** (Ragas).

**O-3 — Reproducibility is pinned at the model and stated at the environment.**
The revision is pinned in code; the library versions are not. `requirements.txt` carries no version constraint on any entry, and adding one only for `sentence-transformers` would diverge from the file's convention. Embeddings are byte-identical across executions on a fixed environment (§4.4), and cross-environment bitwise identity is not claimed by any specification. §4.6 records the exact resolved versions so a future execution can reconstruct this one. Whether this repository wants pinned dependency versions is a repository-wide question, not an embedding question.

**O-4 — First non-trivial cost in the test suite, and it is large.**
Measured: **1.57s → 96.36s**, a ~60× increase. It is concentrated almost entirely in one file — `tests/test_data_quality.py` alone accounts for 81.3s of it, because DQ-7 builds the Index over all 259 committed chunks in each of four specifications (~17s per build, plus a ~5s model load). `tests/test_indexer.py` costs 7.7s; everything else remains ~8s.

Two ways to reduce it were considered and **both declined for stated reasons**:

- *A per-text memoization cache inside the provider* would remove most of the cost and would make `test_m201_determinism_holds_across_provider_instances` pass by construction — a specification that can no longer fail is not one. Only the loaded **model** is cached; never a vector.
- *A session-scoped Index fixture in `tests/test_data_quality.py`* would work and weakens nothing, but it contradicts the reasoning that file records at `index_over`: the Index is deliberately rebuilt per specification because it is **not** a committed artifact and a fixture *"would read like an artifact reader beside `real_chunks`, and it is not one."* Overturning that is a judgement about the validation layer's own conventions, and it is worth the Repository Owner's decision rather than a silent change inside an embedding sprint.

If suite time becomes the binding constraint, the fixture is the honest fix and the cache is not.

**O-5 — The dependency is heavier than the model.**
`sentence-transformers` pulls `torch`, and on this platform `pip` resolved CUDA-enabled wheels (~2 GB installed) although the provider forces `device="cpu"`. Nothing is broken by this and no repository capability requires GPU execution — `docs/roadmap.md` §7 places *"GPU optimization"* out of scope. A CPU-only wheel index would reduce the install substantially; that is an environment provisioning choice, not a code change, and is recorded rather than acted on.

**O-6 — No query-side embedding exists yet, by design.**
BGE's asymmetric retrieval prefix (*"Represent this sentence for searching relevant passages:"*) applies to **queries**, not passages. Every text this seam sees today is a chunk, and this sprint implements no retrieval, so no prefix is applied and the single-method `embed` seam is sufficient. **The sprint that implements the vector route (M2-02 / M2-04) will have to decide** whether the query side needs its own entry point — that decision is a retrieval decision and is correctly not made here.

**O-7 — An unrelated staleness observed, not corrected.**
`sample_rag/README.md` closes by describing job descriptions and JobOps data as *"Milestone 1B capabilities — **1B-05**, **1B-06**"*. Ruling **RO-06** reallocated both to Milestone 2B. This predates the sprint, is outside its scope, and was left untouched.
